# Deploy BuildNova AI — free permanent link

BuildNova AI is a zero-dependency Node.js web server (no build step). It reads
`process.env.PORT`, serves the frontend, and **auto-creates demo data on first
boot**, so a fresh deployment starts from the correct demo state (PIP-0453 Not
Started). The recommended free host is **Render**.

---

## Option A — Render Blueprint (auto, ~3 minutes)

1. **Push to GitHub** (the repo folder itself must contain `package.json` and
   `render.yaml` at its **root** — no wrapper folder):
   ```bash
   cd /path/to/buildnova          # the repo root (has package.json)
   git init && git add . && git commit -m "BuildNova AI — SIH 2026"
   git branch -M main
   git remote add origin https://github.com/<your-user>/buildnova-ai.git
   git push -u origin main
   ```
2. https://dashboard.render.com → **New** → **Blueprint** → connect GitHub →
   select the **buildnova-ai** repo.
3. Click **Apply** and wait ~1–2 minutes.
4. Open the URL Render shows (e.g. `https://buildnova-ai-sih2612.onrender.com`).

> **If the Blueprint fails with a plan error** — remove the `plan: free` line
> from `render.yaml`, commit, and Apply again, choosing **Free** in the pop-up;
> or skip Blueprint and use **Option B** below.

## Option B — Render Web Service (manual, most reliable)

If the Blueprint path errors, a plain Web Service avoids all `render.yaml`
parsing:

1. Push the repo to GitHub (step 1 above).
2. https://dashboard.render.com → **New** → **Web Service** → connect the repo.
3. Fill in **exactly**:
   - **Name:** `buildnova-ai-sih2612` (or anything free/unique)
   - **Environment:** `Node`
   - **Region:** nearest (e.g. Singapore) — anything works
   - **Branch:** `main`
   - **Root Directory:** *(leave blank — repo root)*
   - **Build Command:** `npm install --omit=dev`
   - **Start Command:** `node server/server.js`
   - **Plan:** `Free`
   - *(Optional but safest)* under **Environment** add `NODE_VERSION = 20.18.0`
4. **Create Web Service**. Wait ~1–2 minutes → **Live**.

## Verifying

- `https://<your-url>/api/health` → `{"ok":true}`
- Login screen loads (role **dropdown**, any password). Sign in as **Planner**
  and run the judge walkthrough.
- Footer / sidebar shows **build 20260909e** on the deployed copy.

## Troubleshooting ("deploy failed")

| Symptom / error | Cause | Fix |
|---|---|---|
| `no such plan free for service type web` | `plan: free` rejected for your account | Remove `plan: free` (Option A) or use Option B and pick Free in the UI |
| Blueprint "render.yaml not found" | Repo root is a wrapper folder | Put `render.yaml` + `package.json` at the repo **root** (the folder you `git init` in) |
| **Application error / exited** after build | Server bound the wrong port or crashed on boot | Start command must be `node server/server.js`; it binds `0.0.0.0` on `process.env.PORT` automatically. Verify locally with `npm start`. |
| **Name is already taken** | The `.onrender.com` subdomain is global | Rename the service (e.g. `buildnova-ai-sih2612`) |
| Build succeeds but page stays down / health fails | Node version too old, or startup > Render's limit | Our app starts in <1 s; set `NODE_VERSION=20.18.0` and confirm start command |
| Vercel/Netlify/GitHub Pages | Static/function hosts only | Not supported — this is a long-running Node server (use Render/Koyeb/Railway) |

**Quick local check before deploying** (catches most issues):
```bash
npm start            # runs on http://localhost:4730
npm test             # self-contained battery; boots its own server
```

## Free-tier notes

- Sleeps after ~15 min idle; first visitor waits ~30–50 s while it wakes.
- Disk resets on redeploy → app re-seeds the clean demo baseline (ideal for
  hackathon demos).
- To keep it warm during judging, open the URL once beforehand.

## Configuration

- `PORT` — set by the host automatically (defaults to `4730` locally).
- No env vars or secrets required; demo data is generated by `server/seed.js`.
